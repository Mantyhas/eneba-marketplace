# Eneba Marketplace — internship assignment

An unofficial digital-game marketplace demo. React + TypeScript, Go REST API and PostgreSQL. No Docker required. All sellers, prices and digital keys are fictional; no real payments or redeemable keys.

## Windows setup (VS Code / PowerShell)

Prerequisites: Git, Go 1.23+, Node 22+, and PostgreSQL 15+ (including pgAdmin or SQL Shell). Install PostgreSQL from https://www.postgresql.org/download/windows/ and remember the password for the `postgres` user. Start the PostgreSQL Windows service. Open the extracted project root in VS Code.

### 1. Database

In pgAdmin, connect to the local server. Create a database named `eneba_marketplace` (right-click Databases → Create → Database). Open Query Tool **on that database**, open `backend/migrations/001_init.sql`, and execute it. Then open and execute `backend/seeds/001_demo.sql`. The seed is repeatable and does not reset sold inventory.

Alternatively, if `psql` is on PATH, from project root:

```powershell
psql -U postgres -d postgres -c "CREATE DATABASE eneba_marketplace;"
psql -U postgres -d eneba_marketplace -v ON_ERROR_STOP=1 -f backend/migrations/001_init.sql
psql -U postgres -d eneba_marketplace -v ON_ERROR_STOP=1 -f backend/seeds/001_demo.sql
```

### 2. Backend (terminal 1)

```powershell
cd backend
Copy-Item .env.example .env
```

Edit `.env`: replace `YOUR_PASSWORD` with your PostgreSQL password (URL-encode special characters in the password). Leave the port and frontend origin as provided. Never commit `.env`.

```powershell
go mod tidy
go test ./...
go run ./cmd/api
```

Open http://localhost:8080/api/health — expected `{"status":"ok"}`. Open http://localhost:8080/api/products — expected JSON catalog.

### 3. Frontend (terminal 2, from project root)

```powershell
cd frontend
Copy-Item .env.example .env
npm install
npm run build
npm run dev
```

Open http://localhost:5173. Register with a fictional email and a password (8–72 bytes), select a game and seller, add to cart and pay with demo payment. The purchased demo key appears under My orders (user icon). No real credentials or card details are needed.

## Architecture

See [architecture](docs/architecture.md), [API](docs/api.md) and [test plan](docs/testing.md). One Go module with feature packages under `internal/modules`, one PostgreSQL database, one React SPA. Native Go 1.23 HTTP router, pgx SQL driver, bcrypt passwords, random opaque expiring session tokens stored hashed in PostgreSQL. Token kept in sessionStorage for the demo; server validates protected routes. Cart identifiers and quantities are kept locally, but prices, availability and key allocation are always server-controlled. Money is integer euro cents. Checkout locks offers and keys in a transaction, and verifies expected total before commit. No payment provider or production credentials.

## Deployment (not yet deployed)

Use a Go-compatible host that supports native builds and a managed PostgreSQL instance with `pg_trgm`. Apply migrations and seeds to that database. Set `DATABASE_URL`, `PORT` as supplied by hosting and `FRONTEND_URL` to the exact public frontend origin. Build from `backend` with `go mod download && go build -o api ./cmd/api`, start `./api`. For Vercel choose `frontend` as root, Vite framework, `npm run build`, output `dist`, and `VITE_API_URL=https://YOUR-BACKEND/api`. Use HTTPS and check CORS, health, and purchase flow. Confirm current hosting free tier before choosing a provider. No deployment account or public URL has been created.
